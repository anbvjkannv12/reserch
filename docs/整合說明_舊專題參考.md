## 一、兩個資料夾的關係（重要結論先講）

這兩個資料夾**不是兩個獨立專題，而是同一個研究的兩個階段**：

- **`專題`（舊）**：2026-06-02～08-05 執行，使用 **3 年**歷史資料（`btc_3y.csv` 等），完整跑過 XGBoost、LSTM、Transformer（含 PyTorch 版）在 1h／4h／12h／24h 四種預測窗口的分類與回歸實驗，並完成 Week 1–5 的比較文件。這是模型探索最完整、實驗最多的階段。
- **`專題 new (五年)`（新，本資料夾）**：2026-08-10 起執行，把資料換成 **5 年**歷史資料，並重新用更嚴謹的工程流程（資料驗證、補值、TDD 測試、walk-forward 防洩漏）把資料管線做過一次。`agement.md` 裡明確寫「確認並沿用原專題中完全相同的特徵與標籤定義」，代表**新資料夾的特徵工程本來就是延續舊資料夾的成果**，只是換了資料筆數與底層程式碼。

也就是說：**舊資料夾的「資料」已經過時（3 年 < 5 年），但舊資料夾的「LSTM／Transformer 模型程式碼、實驗方法、週報比較結論」大多還沒有在新資料夾重做過**——新資料夾目前只做了 XGBoost baseline 和一套新的三模型比較（`btc_4h_evaluation.py`），4 小時單一窗口、四幣種，還沒有像舊資料夾那樣做完整的 1h/12h/24h 多窗口比較。

另外有一個目前正在運作中的依賴關係：**新資料夾的模型比較腳本，實際上是用舊資料夾裡的 `C:\Users\user\專題\.venv-transformer` 虛擬環境執行的**（`docs/eth_4h_model_comparison.md` 有記錄，因為新資料夾內建的 Codex runtime 沒有裝 `torch`）。所以在真正把兩邊分開之前，舊資料夾至少這個虛擬環境還在被使用中，不能直接刪除。

| 檔案 | 為什麼有用 |

| `log_return_regression_comparison.md` | 完整記錄「回歸預測報酬率」為什麼是負結果，新專題完全沒做回歸，這份文件可以直接支撐新報告「本階段聚焦方向分類、不做回歸」的決策依據。 |
| `multi_horizon_experiment_guide.md` | **最關鍵的一份**：裡面已經寫好「如何把 3 年資料換成 5 年資料」的設定範例（`coin_files_5y`、`max_train_size=17520`），以及逐幣種逐 horizon 的模型參數表，還有一個 `cost_aware_target` 的「三段式目標（漲／跌／不交易）」helper function 說明——這正是新專題時程裡列為「10 月之後未來工作」的「三段式目標評估」。等於舊專題已經先把架構搭好了，可以少走一段路。 |
| `btc_24h_pytorch_transformer.md` | PyTorch 版 Transformer 的訓練與推論說明（含 checkpoint 存讀），跟新專題的 TensorFlow/簡易 Transformer 是不同實作，多一個可比較的版本。 |
| `agent.md` | 舊專題完整八週規劃與每週進度紀錄，可以看到「為什麼選 12h 當主軸」「為什麼回歸被放棄」等決策脈絡，寫報告方法論／研究過程時很有用。 |

### 程式碼（`舊專題參考\src\`、`舊專題參考\tests\`）

| 檔案 | 為什麼有用 |
| --- | --- |
| `multi_horizon_experiment_utils.py` | 完整封裝好的 `run_xgboost`、`run_sequence_model`（LSTM/Transformer 共用）、`build_lstm_model`、`build_transformer_model`、walk-forward 切分等函式，支援多幣種、多 horizon、逐一設定模型參數。新專題目前的 `btc_4h_evaluation.py` 是重新寫的一套精簡版本，只做 4h；如果要做 1h/12h/24h，這份程式碼可以省下重寫的時間。 |

| `tests/` 三個測試檔 | 對應上述程式碼的單元測試，方便你之後要在 5 年資料上重跑時，先確認函式行為沒有跑掉。 |
